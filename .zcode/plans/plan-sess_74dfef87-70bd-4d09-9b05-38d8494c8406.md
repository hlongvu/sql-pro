# TablePlus-style UX and feature parity pass

## Goal

Rework SQL Pro into a coherent TablePlus-style desktop database client for the engines this repository actually supports (SQLite, PostgreSQL-family, and MySQL-family). The implementation will reproduce TablePlus’s information architecture and interaction model using original Rust/GPUI code and SQL Pro branding; it will not copy proprietary code, trademarks, or assets.

The target is current TablePlus 27.1-era behavior: workspace rail, Items/Queries/History navigation, real object/query tabs, editor-over-results query tabs, dense spreadsheet grid, row details, Open Anything, staged Discard/Preview/Commit, environment-aware status, and keyboard-first operation.

No further design questions are needed. Unsupported capabilities will be hidden or explicitly disabled rather than represented by controls that silently do nothing.

## 1. Replace the single global result model with isolated workspaces and tabs

- Introduce explicit application models under `crates/app/src/workspace/`:
  - `DatabaseWorkspace`: connection identity, driver, discovered objects, connection state, tabs, active tab, navigation state, and environment color/tag.
  - `WorkspaceTab`: stable ID, title, preview/pinned state, dirty state, operation state, and one of `Table`, `Query`, or `Message` content.
  - `ResultSetState`: columns, rows, original rows, row IDs, selection, structure, count, elapsed time, filters, sorts, paging, and pending changes.
  - `ResultOrigin`: connection ID plus exact schema/table provenance; only a table-browse origin is editable. Arbitrary SQL results and views remain read-only unless provenance is explicit.
- Support multiple live database workspaces in one window. Switching the workspace rail changes the active database without replacing another workspace’s tabs or pending edits.
- Implement TablePlus preview-tab behavior: a normal object click reuses the unmodified preview tab; pin/open-in-new-tab preserves it; query tabs and tabs with edits are never replaced.
- Keep one rendered grid adapter but swap it from the active tab model, preserving selection and pending state per tab. Query editors remain separate `EditorState` entities per query tab.
- Add request IDs/generations to connection, table-load, metadata, query, and save callbacks so stale async completions cannot overwrite newer workspace/tab state.

## 2. Make the editing and save model trustworthy before exposing TablePlus controls

- Bind every pending change and save plan to a connection ID, tab ID, exact table/schema, column snapshot, and revision.
- Serialize operations per workspace. Save/commit sets a busy state, prevents duplicate commits, and clears only the exact revision that completed successfully.
- Preserve newly staged edits if they appear after a save snapshot rather than calling an unconditional `pending.clear()`.
- Keep table edits alive while switching tabs/workspaces. Closing, replacing, refreshing, or disconnecting a tab with pending work opens a real Discard/Cancel confirmation instead of silently clearing it.
- Use dialect-aware identifier quoting for all table browse/reload/count/filter/sort SQL, fixing MySQL table opening.
- Distinguish explicit `NULL`, empty string, `DEFAULT`, literal text, and intentional SQL expressions in the change model. Plain text such as `NOW()` or `__DEFAULT__` will no longer be reinterpreted automatically.
- Prevent inline editing of binary/unsupported decoded values; display them as typed placeholders with copy/inspect actions rather than allowing `<binary>` to be written back.
- Tighten affected-row verification: zero-row keyed writes fail where the engine/write kind provides reliable semantics, while preserving MySQL’s no-op update exception.
- Ensure write-plan epilogues run after both success and failure.
- Make MySQL transactions use one physical session for `BEGIN`, all parameterized steps, and `COMMIT`/`ROLLBACK` instead of returning each step to the pool.

## 3. Rebuild the connected window around TablePlus’s hierarchy

- Replace the current two wide left panes with:
  - A narrow database/workspace rail showing open connections, status color, active state, add connection, and return-to-welcome affordance.
  - One navigator with `Items`, `Queries`, and `History` tabs, each with its own search state and actions.
- Add a real tab strip across the content area with table/view/query icons, close controls, dirty/pending indicators, preview state, and `+` query action.
- Make content tab-specific:
  - Table tabs show Data/Structure modes and table controls without a permanently visible SQL editor.
  - Query tabs show an editor above result tabs/messages with a compact run bar.
- Replace the current toolbar with a dense TablePlus-style toolbar containing sidebar/workspace controls, connection/database identity, segmented Discard/Preview/Commit, safety level, reload, Open Anything, console, and row-details toggles.
- Keep the user’s established preference that query-specific actions live in the query panel rather than the global toolbar.
- Remove the placeholder Assistant pane. The right sidebar becomes a focused row-details inspector, toggled by `Space`, with copy actions and clear empty states.
- Keep the collapsible console and make status/error/progress information consistent across toolbar, result footer, and notifications.

## 4. Match the visual language, density, and states

- Refactor `crates/app/src/theme.rs` into semantic tokens for window chrome, navigation, tabs, grid, editor, connection state, selection, inserted/modified/deleted rows, errors, and notifications.
- Use a compact monospaced data/editor treatment (12 px target), 24–30 px rows, one-pixel dividers, restrained native surfaces, and minimal decorative card styling.
- Adopt a Silver Dark-style charcoal default and a warm neutral light palette while preserving SQL Pro’s blue accent and current light/dark switch.
- Use a clear red active-cell outline, green inserted rows, amber modified rows, and red/pink deleted rows. Preserve alternating grid rows and connection environment color.
- Retain Unicode button glyphs because SVG toolbar icons have previously failed to render in this app.
- Keep the welcome screen as the user-preferred bounded centered chooser, but add TablePlus-style connection search, dense two-line rows, status tags/colors, and connection management actions.

## 5. Implement real query and table workflows

### Query tabs

- Make `Cmd/Ctrl+E` and `Cmd/Ctrl+T` create actual query tabs instead of clearing one global editor.
- Implement `Run Current` from selected text or the statement at the caret, and `Run All` for the complete editor. Statement extraction will use the repository splitter only after extending its handling for comments, backticks, nested PostgreSQL comments, and MySQL escapes.
- Expose separate Data and Message result modes with elapsed time, affected/returned rows, errors/notices, and export action.
- Where the driver returns multiple statement results, surface numbered/named result tabs rather than discarding all but the final result; extend the driver façade if required while retaining the existing single-result convenience API.
- Add close/close-others/close-right tab actions and keyboard navigation (`Cmd/Ctrl+1…9`, bracket navigation where GPUI permits).

### Table tabs

- Use TablePlus’s default 300-row page size with previous/next paging, limit and offset state, row range, and estimated/exact count behavior.
- Cycle column-header sorting through descending, ascending, and none; support multiple sort columns through the header/context menu.
- Add the bottom filter bar (`Cmd/Ctrl+F`) with column/operator/value conditions, AND/OR mode, enabled state, generated-condition preview, Apply, and Clear. Filters run server-side through dialect-safe SQL generation.
- Keep Data and Structure views. Structure remains read-only until driver metadata can safely support schema mutation; no fake Index/DDL editor will be shown.
- Expand grid context actions for edit, explicit NULL/empty/default, copy cell/row formats, duplicate, insert, delete/restore, refresh, quick filter, and export.
- Keep staged row coloring and make modified cells visually identifiable, not only the containing row.

## 6. Add TablePlus’s signature navigation tools

- Implement `Cmd/Ctrl+P` Open Anything as a Spotlight-style overlay that fuzzy-searches tables/views, open workspaces, saved queries, history, and application actions.
- Support keyboard traversal, Enter to open, modified Enter to open in a new tab, and two-stage Escape behavior.
- Add common command entries for new query, reload, toggle sidebar/details/console, theme, connection/database switch, and focus filter.
- Implement `Queries` as a file-backed saved-query list with folders/names and safe atomic persistence. Add Save Query/Rename/Delete/Open actions and preserve ordinary `.sql` content.
- Upgrade `History` to use the existing SQLite/FTS backend: active-connection filtering, full-text search, success/error state, timestamp/duration, pagination, load into a new query tab, delete, and clear actions.
- Run the existing 10,000-entry/90-day retention cleanup at startup/periodically so the UI’s retention promise is true.

## 7. Enforce safety instead of displaying a cosmetic badge

- Persist a connection safety level and enforce it before query execution and GUI commit:
  - Off: execute normally.
  - Warn Writes: read-only statements run; writes/DDL require confirmation.
  - Protect All: every execution requires a confirmation that prominently names the connection/database and environment tag.
- Treat unknown/unparseable statements as risky, so the control fails safe rather than implying protection it cannot provide.
- Give production-tagged connections a prominent status treatment and require stronger confirmation for destructive statements.
- Add generated SQL Preview for staged changes. It will show each parameterized statement, bound values, target connection/table, and row count before Commit, with copy and close actions.
- Make Discard a real confirmation and reload only the affected table tab after acceptance.

## 8. Make connection management honest and reliable

- Limit the connection picker to engines backed by the binary, with compatible families clearly labeled; do not offer unsupported engines as connectable choices.
- Make Test call `ping`, and make Connect fail when table discovery or authentication fails instead of reporting “Connected — 0 tables.”
- Add edit, duplicate, delete, reconnect, and disconnect actions for saved connections.
- Make connection persistence atomic and propagate failures to the UI rather than reporting false success.
- Stop logging imported URLs containing credentials.
- Move persisted passwords behind an OS secret-store abstraction. Connection JSON will not contain plaintext passwords; if the platform secret store is unavailable, the UI will keep the password session-only and say so.
- Wire supported TLS modes into PostgreSQL/MySQL transport or hide modes that cannot be honored. SSH and certificate controls remain absent/disabled until a real tunnel/certificate implementation exists; no control will claim an inactive protection.
- Build PostgreSQL configuration with typed setters rather than interpolated keyword strings.

## 9. Improve export without pretending to implement every TablePlus backend feature

- Replace the fixed `~/sqlpro-export.csv` overwrite with an export sheet for the active result/table, destination selection/path, overwrite confirmation, and atomic output.
- Support CSV and JSON immediately using existing row/value primitives; add SQL export only where identifiers and values can be generated safely.
- Fix single-row CSV copy to emit a header line followed by one data line.
- Full multi-table export, CSV mapping import wizard, backup/restore, ER diagrams, editable schema/index/trigger designers, multiple windows, charts, SSH tunnels, and the entire TablePlus driver catalog are deliberately outside this pass because the current driver façade cannot implement them honestly. Their entry points will not be shown as working features.

## 10. Refactor and verify

- Split the monolithic `crates/app/src/workspace.rs` into focused state, actions, render, dialog, query, and table modules while preserving GPUI’s known height-chain, modal occlusion, root notification, and crate-root test constraints.
- Add core unit tests for browse SQL, filter/sort/paging, safety classification, explicit value semantics, SQL preview, row-count verification, and epilogue handling.
- Add driver tests for MySQL single-session transactions, PostgreSQL typed configuration/TLS selection, dialect-correct browsing, and connection validation.
- Add headless GPUI tests for welcome, main shell, workspace switching, tab creation/replacement, Open Anything, filter bar, SQL preview, safety confirmation, pending-change guards, and narrow/default/wide window rendering.
- Run `cargo fmt --all -- --check`, `cargo check --workspace --all-targets`, `cargo test --workspace --all-targets`, and Clippy when the component is available. Launch the app for a local smoke test after automated validation.
- Review the final diff and worktree for unrelated changes; no commit or push will be made unless explicitly requested.

## Acceptance criteria

- Pending edits can never be committed to another connection/table or silently lost by query, refresh, tab, or workspace navigation.
- Every visible toolbar/menu control performs its advertised action; unavailable backend features are not presented as active.
- SQLite, PostgreSQL, and MySQL-family table browsing use correct quoting and support paging, filtering, and sorting.
- Query tabs, table tabs, Items/Queries/History navigation, Open Anything, row details, console, and Discard/Preview/Commit behave as one consistent keyboard-first workflow.
- MySQL GUI commits are transactional on one session, duplicate saves are blocked, and async results cannot overwrite newer state.
- The full workspace builds and renders in dark/light themes at common window widths, and all automated tests pass or any external-service gaps are reported explicitly.
